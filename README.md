# GambitRP - бот заявок

Заявки на возврат привилегии и «не пришёл донат» принимает Telegram-бот
[@gmbt_support_bot](https://t.me/gmbt_support_bot). Заявка сохраняется в
Supabase, админ получает её в чате с ботом и там же отвечает игроку.

Раньше заявки шли через сайт с входом через Discord. У игроков из России не
открывался Vercel и был заблокирован discord.com, поэтому всё перенесли в бота,
а сайт оставили заглушкой со ссылкой на него. Исходный план сайта лежит в
[PLAN.md](PLAN.md), это история.

```
api/telegram.js   вебхук бота (Vercel Edge Function)
api/_bot.js       бот: анкета, карточки, переписка, панель (не маршрут)
validators.js     списки вариантов и проверки ответов анкеты
supabase.sql      таблицы, выполнить один раз (повторный запуск безопасен)
index.html        заглушка сайта со ссылкой на бота
```

## Развёртывание

Блокировка Vercel боту не мешает: вебхук вызывают серверы Telegram, а не
телефон игрока.

1. Выполнить [supabase.sql](supabase.sql) в Supabase → SQL Editor.
2. Импортировать репозиторий в Vercel (framework preset: **Other**, build command пустой).
3. Заполнить переменные из [.env.example](.env.example) в настройках проекта
   Vercel и задеплоить. Переменные подхватывает только новый деплой.
4. Подключить вебхук. Открыть в браузере, подставив токен, домен и секрет:
   `https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<домен>/api/telegram&secret_token=<SECRET>&max_connections=1&allowed_updates=["message","callback_query"]`
   `max_connections=1` - апдейты идут по одному, и два быстрых нажатия не
   перетирают друг другу черновик. Проверка: `getWebhookInfo`, поле
   `last_error_message` должно быть пустым.
5. Написать боту `/start` с админского аккаунта. Бот сам выставит меню команд:
   всем - `/start`, `/my`, `/cancel`, админам - ещё `/panel`. Игроки `/panel`
   не видят.

Вебхук всегда отвечает Telegram 200, даже при ошибке, чтобы тот не повторял
апдейт. Поэтому чистый `getWebhookInfo` не значит, что бот работает. Если бот
молчит, смотреть Vercel → Logs:
- `апдейт без верного секрета` - секрет в Vercel не совпадает с `setWebhook`
  или после его смены не было Redeploy;
- `relation "tg_state" does not exist` или `"tg_blocked"` - не выполнен свежий
  [supabase.sql](supabase.sql). Выполнять его **до** деплоя новой версии бота:
  блокировка проверяется на каждом сообщении игрока.

## Как работать с заявками

Всё делается в чате с ботом, с аккаунта из `ADMIN_IDS` (по умолчанию `TELEGRAM_CHAT_ID`).
Внизу чата - кнопка `📋 Все заявки` (появляется после `/start`), в меню команд - `/panel`.

- Новая заявка приходит сама: карточка с кнопками и файл под ней.
- `На рассмотрении / Выдано / Отказано` - меняют `status` и сообщают игроку. После
  «Выдано» или «Отказано» заявка закрыта: игрок по ней больше писать не может,
  только подать новую.
- `💬 Ответить` - бот просит написать сообщение, и **одно** следующее сообщение
  (текст, фото, файл, голосовое) уходит игроку. Режим держится 15 минут; команда,
  кнопка клавиатуры или «✖ Отмена» снимают его. Ответ через Reply на карточку или
  на сообщение игрока тоже работает.
- `🚫 Заблокировать` / `✅ Разблокировать` - заблокированный не может ни подать
  заявку, ни писать в поддержку, бот отвечает ему «Вы заблокированы». Твои ответы
  ему доходят. Разблокировать можно с любой его карточки (найти - через панель).
- Что пишет игрок по открытой заявке, приходит ответом на её карточку.
- `📋 Все заявки` - список с фильтром по статусу, листанием и открытием любой
  заявки, в том числе старых с сайта.

У игрока внизу чата кнопки `📝 Подать заявку` и `📄 Мои заявки` (свои заявки со
статусами), под каждым вопросом анкеты - `✖ Отмена`.

Таблица `requests` в Supabase → Table Editor по-прежнему доступна. Там же
заметки `admin_note`, которые игрок не видит.

Что проверяет бот:
- Выдуманные SteamID не проходят: при заданном `STEAM_API_KEY` ID сверяется с
  профилем в Steam.
- Лимит - 3 заявки в час и 10 в сутки на один Telegram-аккаунт.
- Если игрок прислал сжатое фото вместо файла, его просят прислать файл, а в
  карточке появляется пометка `⚠ Telegram сжал фото`.

Файлы из бота не копируются в Supabase: в базе лежит `tg_file_id`, сам файл
остаётся в Telegram и пересылается админу без скачивания. Скриншоты старых
заявок с сайта лежат в bucket `screenshots`. Ссылки на них в `screenshot_url`
перестают работать через год после выдачи.
