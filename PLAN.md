# GambitRP - сайт заявок (план)

## 1. Задача

Заменить ручные обращения в Discord структурированными заявками. Игрок выбирает проблему →
читает гайд → заполняет форму → заявка падает в Telegram и в базу. Ответ управляющий даёт
в Discord (контакт берётся из формы).

Успех = заявка приходит полной, без раунда уточнений «а скинь SteamID / а скрин обрезанный».

## 2. Структура сайта

Одна страница, без роутера и фреймворка.

```
Экран 1 - выбор проблемы (выпадающий список / 2 карточки)
   ├── «Нужно вернуть привилегию»  → Экран 2а
   └── «Не пришёл донат»           → Экран 2б

Экран 2 - гайд + форма (гайд сверху, форма снизу, на одной странице)
Экран 3 - подтверждение отправки (свой текст на каждый тип)
```

## 3. Сценарий А: «Нужно вернуть привилегию»

### 3.1 Гайд (текст выше формы, из Telegraph-статьи)

**Привилегию возвращаем только в 3 случаях:**
1. **После наборки** - занял пост наборного администратора, имея донатную привилегию.
2. **Автоснятие** - система сняла за спам ULX-командами (защита от слива админки).
3. **Забыли снять варны с прошлой админки** - сняло по лимиту (5 варнов), которых на текущей привилегии не было.

**Привилегию НЕ возвращаем, если:**
- это VIP (только донатные админки от д-модера и выше);
- утеряна более полугода назад (для наборной - отсчёт с момента снятия с наборки);
- сняли с донатной админки, а вернуть пытаешься более старую;
- отсутствует лог покупок.

*Возможен отказ и по причине, не указанной выше.*

**Где взять SteamID:** на сервере открой TAB → найди себя → «Скопировать SteamID».

**Где взять лог покупок:** F4 → Донат → иконка профиля справа сверху → «Все логи» →
скриншот с покупкой нужной привилегии.

**Скриншот - от угла до угла экрана.** Обрезанные скриншоты и фото монитора не принимаются.

### 3.2 Отсечение до формы

Перед кнопкой «Заполнить заявку» - обязательный чекбокс:
«Я прочитал условия выше, моя ситуация подходит под один из 3 случаев, у меня есть полный
скриншот лога покупок». Без галки форма не открывается.

### 3.3 Поля формы

| Поле | Тип | Обязательное | Валидация |
|---|---|---|---|
| SteamID | text | да | формат `STEAM_0:[0-1]:\d+` |
| Причина пропажи привилегии | select (3 варианта из гайда) | да | - |
| Скриншот лога покупок | file | да | jpg/png/webp, ≤ 5 МБ, ширина ≥ 70% ширины экрана игрока |
| Ваш Discord | text | да | ник или `@ник`, 2-37 символов |
| Комментарий | textarea | нет | ≤ 500 символов |

Подпись у поля файла: «ПОЛНОСТЬЮ виден весь экран. Обрезанные скриншоты не принимаются».
Ширина картинки читается через `Image()` и сравнивается с `screen.width` игрока: меньше 70%
- почти наверняка обрезок. Порог относительный, поэтому не зависит от разрешения монитора.

### 3.4 Экран подтверждения

> Привилегия будет выдана в течение дня.

## 5. Стек

| Слой | Что | Почему |
|---|---|---|
| Фронт | статический HTML + CSS + vanilla JS | 2 формы, фреймворк не окупается |
| Хостинг | Vercel | выбран заказчиком, деплой из git |
| Бэкенд | 1 serverless-функция `api/submit.js` на Vercel | токены нельзя держать в браузере |
| БД + файлы | Supabase (Postgres + Storage) | бесплатный тариф, готовый табличный админ-интерфейс - свою админку писать не нужно |
| Уведомления | Telegram Bot API `sendPhoto` / `sendMessage` | - |

**Cloudflare Worker не нужен** - раз хостинг на Vercel, серверная часть живёт там же, в том же
репозитории. Аккаунт Cloudflare пригодится позже: для домена (DNS) и для Turnstile, если пойдёт спам.

## 6. База данных

Таблица `requests` в Supabase, доступ через Table Editor (это и есть админка: фильтры,
правка статуса, заметки).

```sql
create table requests (
  id             bigserial primary key,
  created_at     timestamptz not null default now(),
  type           text not null check (type in ('privilege','donate')),
  steam_id       text not null,
  discord        text not null,
  reason         text,          -- сценарий А
  amount         integer,       -- сценарий Б
  payment_method text,          -- сценарий Б
  paid_at        timestamptz,   -- сценарий Б
  screenshot_url text,
  comment        text,
  status         text not null default 'new'
                 check (status in ('new','in_progress','done','rejected')),
  admin_note     text,
  ip_hash        text           -- sha256(ip + соль), для лимитов; сам IP не храним
);
create index on requests (created_at desc);
create index on requests (status);
```

RLS включён, публичных политик нет - писать может только функция по service-ключу.
Bucket `screenshots` приватный, в заявке хранится подписанная ссылка (срок 1 год).

переменной окружения.

## 8. Защита

Ставим сразу (дёшево, без внешних сервисов):

1. **Honeypot** - скрытое поле, заполнено → тихо отбрасываем (отвечаем «ок», в базу не пишем).
2. **Тайминг** - форма отправлена быстрее 3 секунд после открытия → отбрасываем.
3. **Rate-limit по `ip_hash`** - не больше 3 заявок в час и 10 в сутки с одного адреса.
4. **Валидация файла на сервере** - MIME по сигнатуре, не по расширению; ≤ 5 МБ; только jpg/png/webp.
5. **Все секреты в env-переменных Vercel** - токен бота и service-ключ Supabase в браузер не попадают.
6. **Жёсткая серверная валидация полей** - фронтовая проверка не в счёт, она обходится за 10 секунд.

Держим в резерве, включаем при первом же наплыве спама:

- **Cloudflare Turnstile** (бесплатно, аккаунт CF уже есть) - ~5 строк на фронте + 1 запрос на бэке.

Верификация владения SteamID - **не делается**, проверка ручная (по решению заказчика).
Риск осознан: чужой SteamID в заявке отсекается на этапе ручной проверки лога покупок.

## 10. Решения (вопросы закрыты)

1. **Telegram - личка.** Шлём в личный чат управляющего. Смена на группу = замена одной
   переменной окружения, если поток вырастет.
2. **Supabase** - аккаунт зарегистрирован.
3. **Дата и точное время платежа - обязательное поле** формы доната. Скриншот чека - добавлен
   (необязательный).
4. **Домен** - стартуем на `*.vercel.app`, покупку откладываем.
5. **Доступ к базе - только у управляющего.**

## 11. Порядок работ

| Этап | Что делаем | Блокеры |
|---|---|---|
| 1 | Статика: экраны, гайды, обе формы, валидация на фронте. Работает без бэка | нет |
| 2 | Supabase: проект, таблица, bucket, ключи | вопрос 2 |
| 3 | Telegram: бот через @BotFather, получение chat_id | вопрос 1 |
| 4 | `api/submit.js`: валидация, загрузка файла, запись в базу, отправка в TG | этапы 2-3 |
| 5 | Деплой на Vercel, боевой прогон обеих форм | - |
| 6 | Домен | вопрос 4 |

Этап 1 не зависит ни от чего и стартует сразу.

## 12. Чего сознательно не делаем

- Личный кабинет игрока, статусы заявок на сайте, трекинг по номеру.
- Авторизация через Steam.
- Админ-панель - её роль выполняет Table Editor в Supabase.
- Автопроверка платежей через API платёжных систем.
- Капча (Turnstile лежит наготове, §8).

Добавляем, когда поток превысит ~30 заявок в день или появится конкретная боль.
